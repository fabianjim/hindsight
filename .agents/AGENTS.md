# Hindsight — Agent Guide

Hindsight is the Python AI service behind Vestry, a portfolio journal for reflective investors. Vestry's Java backend is the system of record and the only public API; hindsight is called only by that backend and is never publicly reachable. Vestry must stay fully functional when hindsight is off or down. The AI helps users reflect on their own decisions (what they thought, did, and what happened). It never predicts prices or gives buy/sell advice.

## Working rules

- Explore the affected code and tests before changing anything. When this guide and the code disagree, trust the code, report it, and fix this guide if it was stale.
- Work in small steps. State the next step (files, commands) and wait for approval before creating files or adding dependencies. 
- Ask first for scope expansion, product decisions, spending, publishing, deployment, and changes to the shared database outside the `ai` schema.
- Paid LLM calls (live evals, real-model runs) need explicit approval for each run. Tests use fakes.
- Update this file only when you learn something significant for future agents. Don't log task history here.

## Layout and commands

- `src/hindsight/`: `main.py` (app, `/health`, the `/v1` router), `config.py` (settings from `HINDSIGHT_*` env vars or `.env`), `auth.py` (service token), `db.py` (async SQLAlchemy + psycopg), `models.py` (declarative base, `ai` schema), `budget.py` (AI spend ledger), `spend.py` (`BudgetMiddleware`), `pricing.py` (per-model prices), `llm.py` (LangChain model factory, `UserContext`), `tracing.py` (Langfuse).
- `migrations/`: Alembic, configured in `pyproject.toml` (no `alembic.ini`).
- `contract/openapi.json`: the API contract vestry consumes, generated by `scripts/export_openapi.py`.
- `tests/`: pytest. DB tests need `docker compose up -d`; the `database_url` fixture recreates a `hindsight_test` database and migrates it. `tests/fakes.py` has `FakeToolModel`, a scripted chat model that can call tools.
- Stack: Python 3.13, uv, FastAPI, LangChain 1.x (`create_agent`, middleware; never `langchain-classic`, `LLMChain` or `AgentExecutor`), SQLAlchemy 2 + psycopg 3, Alembic, Langfuse v5, ruff, pyright (strict), pytest.
- Commands:
  - `uv run fastapi dev` (needs `.env` from `.env.example`)
  - `docker compose up -d` (local `supabase/postgres` on port 54322, same version as prod)
  - `uv run alembic upgrade head`, `uv run alembic revision --autogenerate -m "..."`
  - `uv run pytest`, `uv run ruff check .`, `uv run ruff format .`, `uv run pyright`
  - `uv run python -m scripts.export_openapi` after any route change
- CI (`.github/workflows/ci.yml`): lint, format, typecheck, tests; migrations applied to a real Postgres plus `alembic check`; Docker build. Actions are pinned to commit SHAs.

## Invariants (high-risk; verify carefully when touched)

**Access**
- Every `/v1` route requires vestry's service token (`require_service_token`, constant-time compare). Only `/health` is open.
- Hindsight trusts the `user_id` vestry sends. Tools get the user from `runtime.context` (`UserContext`), never from a tool argument the model can fill. `tests/test_llm.py` guards this pattern.

**Data**
- Hindsight writes only to the `ai` schema. Alembic's `include_name` filter ignores every other schema; without it, autogenerate proposes dropping vestry's tables.
- Vestry's tables are managed by Hibernate (`ddl-auto=update`). Read vestry data only through vestry-owned `core_read` views once they exist, never raw tables.
- Demo visitors' data lives in vestry's memory and arrives in the request body. Never persist it.

**Contract**
- `contract/openapi.json` must match the code (`tests/test_contract.py`). Operation IDs are route function names, so they become Java method names.
- Contract changes must be backward compatible. Hindsight and vestry deploy independently, in any order.

**Tracing**
- Langfuse redacts all inputs, outputs and metadata unless code runs inside `capture_content()`, which is only for demo and eval runs.
- Without both Langfuse keys, no client or callback is created.

**Spend**
- Every model call reserves its worst-case cost in `BudgetLedger` before it runs and settles the real cost after. A settlement over the reservation blocks all spending until someone resets `ai.budget.blocked`. Crashed or unsettled work keeps its full reservation.
- Every agent gets `BudgetMiddleware`, listed last so it wraps the model directly and each retry reserves again. It caps `max_tokens`, reads the job from `runtime.context.generation_id`, and only implements the async hook, so a sync `invoke` raises instead of skipping the budget.
- `pricing.PRICES` holds pinned model snapshots only. Changing `HINDSIGHT_CHAT_MODEL` means adding its price; unknown models are refused.

**AI output**
- Numbers (returns, P/L, patterns) are computed deterministically. The LLM extracts, narrates and connects, and must cite entry IDs that the server validates.
